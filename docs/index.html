// ARCHITECTURE

三层决策：何时用模板，何时查原版

技能每次接收请求时按优先级判断走哪条路径，避免不必要的原版源码查阅。模板已验证过字段名和继承链，直接替换占位符即可。

用户请求
  │
  ├─ ① 有模板？ ─── 武器/服装/建筑/资源/配方/Harmony/ThingComp
  │     └─ 直接用模板生成（模板已验证过原版结构）
  │
  ├─ ② 报错/调试？ ─── 红字/白窗/崩溃/NullReferenceException
  │     └─ 查原版源码搜索错误原因（grep 或 dnSpy）
  │
  └─ ③ 无模板的新类型？ ─── 植物/生物/派系/事件/地形/Hediff/研究...
        └─ 查原版 Def 结构 → 模仿写出 → 存储为新模板
远程武器模板 — 替换占位符即生成可用 Def
<!-- 模板已验证 ParentName 继承链: BaseGun → BaseGunWithQuality → BaseMakeableGun → BaseHumanMakeableGun -->
<ThingDef ParentName="BaseHumanMakeableGun">
  <defName><YourDefName></defName>
  <label><YourLabel></label>
  <verbs>
    <li>
      <verbClass>Verb_Shoot</verbClass>
      <defaultProjectile><YourProjectileDefName></defaultProjectile>
      <range>28</range>
      <warmupTime>1.2</warmupTime>
    </li>
  </verbs>
</ThingDef>

// WORKFLOWS

7 套工作流，测试版先行

先生成可进游戏测试的测试版（允许 test. 前缀、引用原版贴图），验证无 bug 后再正规化输出。避免在大量内容完成后才发现根本性错误。

new-mod.md
从零创建项目，生成测试版目录结构与最简 About.xml
add-item.md
往已有 mod 添加武器、服装、材料等物品
add-building.md
添加建筑或工作台，含 comps 配置
patch-vanilla.md
用 XML Patch 或 Harmony 修改原版行为
debug-crash.md
红字、白窗、崩溃的定位与修复流程
formalize-mod.md
测试通过后转正式版：正式 ID、原创贴图、Preview.png
batch-process.md
一次处理多个需求清单，批量生成
